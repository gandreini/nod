The Android and iOS app in `clients/mobile` is an Expo client for a Nod server. It connects with the server address and `NOD_AUTH_TOKEN`, and talks to the same API as the web app.

The phone keeps the address and token in the system keychain, and text and voice messages that haven't reached the server yet. After a restart only the last of them, with nothing after it in the chat, goes out by itself; older ones come back as **Not sent**. A file Nod sent is downloaded again each time it's opened in another app, and those downloads are deleted when the app starts, when the owner disconnects and when the server refuses the token. The copies of photos and files the owner picks are deleted when they are removed from a draft, once their message leaves the queue, and when the owner disconnects or the token is refused. If an upload fails, the reason shows above the message box. Only one voice message plays at a time, and a text file preview shows the first 50,000 characters. Disconnecting also deletes the waiting messages; a refused token keeps them, so they still go out after reconnecting to the same server.

In Apps, **Connect** and **Sign in again** call the same connect route as the web app and open the page that route returns in a browser sheet: the service's sign-in, or Nod's own setup page for an app that needs an address or a key. That page uses the browser's own sign-in to Nod. The list reloads when the sheet closes or the app comes back to the front.

Messages go out one at a time, in the order written, and every request has a deadline: 10 seconds for a text message or an answer to a card, 30 seconds for other requests, 3 minutes for a voice message and 10 minutes for a file upload. A message not yet delivered is shown at half opacity. A text message or a card answer the server hasn't confirmed within 1.5 seconds is sent again on a new connection when the live connection is down or has been quiet for 20 seconds: the app drops its connections to the server and resends it under the same ID, without waiting for the first try. On a healthy connection it waits for the server's answer instead, because some replies, such as an answer to a pending confirmation, take the server a few seconds. A network failure does the same at once. If that second try also fails it says **Waiting for connection** and goes out by itself once the live connection is back. A busy server is tried three more times over about a minute. Any other refusal, and a busy server after those tries, leaves the message **Not sent** with **Try again** and **Delete**; tapping **Not sent** shows the server's reason. **Try again** moves the message to the end of the chat. A voice message the server finds empty is removed and a short notice says so. Text is resent under the same ID, which the server recognises; before a voice message is sent again the app asks the server whether it already arrived, and otherwise uses a new ID. The server sends a keepalive every 15 seconds. When none has arrived for 25 seconds the app drops its connections to the server and reopens the live connection, and a message sent while the live connection is down or quiet first gets a new connection, so it never waits on one the network dropped silently. Dropping connections is Android only, through the app's local `nod-network` module: it cancels the requests to Nod's server and closes the idle connections, leaving other services such as a voice call untouched. While the app is in the background the live connection is closed, and push notifications take over. Back in the foreground the app first drops its connections to the server, cancelling any request still waiting from before (Android drops a backgrounded app's connections about five seconds after it leaves the screen), then reopens the live connection. The server's first event on a new live connection tells the app to reload, so the chat loads once, on the new connection. If the live connection hasn't opened 3 seconds after the return, the app drops its connections again, reopens it and reloads the chat anyway; if that reload fails for a network reason, it tries once more after a second and a half. On Android the app also drops its idle connections each time it comes back to the front and checks every 30 seconds that open connections are still alive.

If the chat can't load at all, the screen shows the server's full reason with a retry instead of a spinner. Once it has loaded, problems show in a pill at the top that ends where the call and menu buttons start; tapping it shows the whole reason with **Try again**. Problems with one action, such as a failed Stop or older messages that didn't load, show above the message box instead, and stay up longer when the text is long. **Stop all work** is disabled while the stop is on its way. A confirmation card answers with the action's own label or **Cancel** (**No** when the action itself starts with "Cancel"), shows delete, remove and trash actions in the error colour, and shows a spinner while the answer goes out. While Nod waits for a verification code or a card's security code, a card under its message says to send the code by itself in the message box, as the web app does. Such a code shows in the chat only as **Verification code sent securely.** or **Security code sent securely.**, and is never kept with the unsent messages; neither is any text that looks like a code, even before the request reaches the phone. Section pages reload their data when they open and when the server reports a change while they are on screen, not while they sit behind another page; a page with a text field scrolls it above the keyboard. On the connect screen, the keyboard's next key moves to the token, and the eye button shows or hides it.

When Nod hands the owner its browser, the app opens the live page full screen on a dark background and leaves an **Open browser** card under Nod's message. The bar at the top has Back, Reload and **Close the browser**; the phone can turn to landscape while the page is open. A tap on the page clicks it, a drag scrolls it, and the text bar types into it, with autocorrect, suggestions and autofill off so the phone neither rewrites nor learns what goes into the page; the bar empties at every tap on the page, so text meant for one field never shows next to the next one. While the app is in the background the page stream pauses, and it resumes on return. Pinching zooms the page up to four times; while it is zoomed a drag moves around it, and taps still click the spot under the finger. Closing keeps the handoff open; **Return to Nod** ends it. Nod's browser itself keeps a desktop-size window, so most sites still show their desktop layout.

## Push notifications

On a fork server with `NOD_FCM_SERVICE_ACCOUNT` set, the Android app can show Nod's new chat messages as notifications while it is closed. The app asks `GET /api/fork/capabilities` after connecting and each time it comes back to the front; an original Nod server answers 404 there, and the app then shows nothing about notifications. When that request fails for a network reason or a server error, the app keeps the features it already knew, so the call button and notification settings don't vanish on a weak connection.

**Settings → Notifications** turns them on for this phone: the app asks Android's permission and registers the phone's Firebase token with `PUT /api/fork/push/devices`. Turning them off, or disconnecting, removes it with `DELETE /api/fork/push/devices`. The first time the chat opens on a server with push, the app asks once.

The server sends one notification for each new Nod message in the web chat, only to phones registered with the server's current access key: after the key changes, older phones are dropped. Disconnecting the app also deletes its Firebase token. It sends none for messages Nod sent on Telegram or WhatsApp, and none older than ten minutes. During quiet hours it sends only the results of the owner's own schedules, which deliver on time like the schedules themselves; every other message written then never sends a notification. The notification shows the start of the message, up to 240 characters, with Markdown removed and known secrets replaced. It passes through Google's Firebase Cloud Messaging. While the app is open the notification is not shown, and opening the app clears Nod's notifications from the tray. Tapping one opens the chat, unless a call is on: then the call stays open. The app registers the phone once per launch and again only when Firebase gives it a new token.

Building the app with push needs the project's `google-services.json` in `clients/mobile`, kept out of Git. Only the release variant uses it; Nod Dev and Nod E2E have no push.

## Voice calls

On a fork server with `NOD_VOICE_ELEVENLABS_KEY` set, the chat shows a phone button next to the menu. It opens a live call with Nod: you speak, and Nod answers aloud in about a second. ElevenLabs handles the microphone, speech recognition, turn-taking and the voice. The Nod server writes the answers.

- **Starting a call.** The app asks the server for a one-time conversation token with `POST /api/fork/voice/session`, so the ElevenLabs key stays on the server. On first use, the server creates its ElevenLabs Speech Engine: only token holders can start a call, and recordings are off. Each session gives the engine a new secret; the server keeps only its hash, and the secret is valid for the next two minutes and for that one call. Leaving the call screen before the call connects cancels it. A call starts only from the phone button: the app ignores `nod://` links from other apps and web pages, which open the chat instead. A second tap on the phone button while a call is opening or open does nothing, and the screen stays on for the whole call. While Nod works on a request from the call, the screen says **Asking Nod…**. If the call can't start, the screen says why and offers **Try again**, plus **Open settings** when the microphone isn't allowed.
- **During the call.** ElevenLabs sends each finished sentence to `/fork/voice/engine` over a WebSocket. That route is outside `/api` and accepts only ElevenLabs' connection carrying the latest secret, bound to the one conversation that session started; a reconnect of the same conversation is accepted, any other is refused. The server streams a short spoken answer from a fast model. Its context is the call so far and the last 20 chat messages (withdrawn ones excluded), not Nod's full agent. A newer sentence cancels the answer in progress.
- **Work for Nod.** The call model can't read apps or act. When a request needs that, it says it is asking Nod and the server sends the owner's own words from the call, verbatim, as a normal chat message. So Nod's full agent does the work with every trust check, exactly as if the owner had typed it. When Nod answers, the app sees the reply arrive in the chat and sends the call a silent cue; ElevenLabs only lets the server speak in answer to a turn, so the cue gives the server its turn to read a short spoken version of Nod's answer; if Nod asks a question, the owner answers aloud and that answer goes to Nod the same way. **Confirmations are never given by voice:** words from a call can't approve an action. When Nod asks to confirm something, the call says the confirmation is on the screen, and the call screen shows the same confirmation card as the chat, answered only with its buttons. Words from the call that aren't a tap close a pending confirmation, as a new chat message does. While a call is on, the app keeps its live connection to the server open even in the background, so Nod's answers keep reaching the call. After the call ends, the answer arrives as usual in the chat and as a notification. The call itself isn't saved to the chat yet.
- **Costs.** Each answer is recorded in Usage as agent/voice and counts against the monthly limit; at the limit the call says so and stops. ElevenLabs bills call minutes separately.
- **The model.** Choose it in **Settings → Models → Voice calls**, by default the fastest model on the main connection.

The short version: `pnpm test` runs the fast tests against a fake Nod server, and `pnpm e2e` and `pnpm e2e:ios` run the app itself on an Android emulator or an iPhone simulator against the same fake server. Neither ever touches a real server, a real phone or a live model.

## Build the app

Run these from `clients/mobile`. Each variant has its own package, so they can sit side by side on one device.

| Command                | App     | Package                 | Use it for                                                                               |
| ---------------------- | ------- | ----------------------- | ---------------------------------------------------------------------------------------- |
| `pnpm android:release` | Nod     | `com.gandreini.nod`     | Everyday use. The code is bundled, and only HTTPS servers are allowed.                   |
| `pnpm android:dev`     | Nod Dev | `com.gandreini.nod.dev` | Development with Metro and fast reload.                                                  |
| `pnpm android:e2e`     | Nod E2E | `com.gandreini.nod.e2e` | End-to-end tests only. Allows plain HTTP so it can reach the fake server on `127.0.0.1`. |

Each command regenerates the `android` folder for its variant, then builds an arm64 APK in `android/app/build/outputs/apk`.

On iOS the app uses the same identifiers as bundle IDs. `pnpm ios:e2e` regenerates the `ios` folder for Nod E2E, installs its pods and builds it for the iPhone simulator in `ios/build`. It needs Xcode and CocoaPods, and a UTF-8 locale (`LANG=en_US.UTF-8`); `pnpm e2e:ios` sets it. The app is iPhone only; on an iPad it runs in a scaled iPhone window.

For TestFlight, `APPLE_TEAM_ID=<team> pnpm ios:release` regenerates the `ios` folder for Nod and archives a signed build in `ios/build/Nod.xcarchive`, and `pnpm ios:upload` signs it for distribution and uploads it to App Store Connect. Both need an Apple account signed in to Xcode. Raise `ios.buildNumber` in `app.json` before each new upload.

## Run the tests

```sh title="Terminal"
pnpm test
```

Unit and delivery tests. They take about a second and need nothing but Node.

```sh title="Terminal"
pnpm e2e
```

End-to-end tests with [Maestro](https://maestro.mobile.dev). The script creates an Android emulator called `nod-e2e` if it is missing, starts the fake server with fresh random tokens, installs Nod E2E and runs every flow in `e2e/flows`. It stops the server and the emulator at the end. It uses the first running emulator, or the device `E2E_SERIAL` names, so a phone connected over `adb` is left alone; set `E2E_SERIAL` when more than one emulator is open. A change under `src`, `assets`, `modules` or `plugins` rebuilds Nod E2E.

```sh title="Terminal"
pnpm e2e:ios
```

The same flows on an iPhone simulator called `nod-e2e`, created from an iPhone 17 Pro if it is missing. `E2E_BUILD`, `E2E_KEEP_EMULATOR` and `E2E_PORT` work the same way. The iOS Keychain keeps the saved connection when the app is reinstalled, so the script resets the simulator's Keychain before each run.

The first Android run needs the Android command-line tools, the `system-images;android-36;google_apis` image for your Mac (`arm64-v8a` on Apple silicon, `x86_64` otherwise), a JDK 17 (from `JAVA_HOME`, else `/usr/libexec/java_home -v 17`) and the Maestro CLI. Set `E2E_BUILD=1` to rebuild Nod E2E first, and `E2E_KEEP_EMULATOR=1` to leave the emulator running between runs. When a run fails, the script keeps the emulator and fake server logs and prints their folder.

## The fake server

`tool/fake-server.mts` is a small Nod stand-in with synthetic data. It uses the server's real access check, so a wrong token gets the same 401 as a real Nod. Tests drive it through `/fixture/*` routes that need a separate control token.

It can also fail on purpose. `/fixture/audio-faults` makes the next voice messages lose their answer on the way back, stop after the server claimed them, be cancelled like a Stop, meet a busy server, or get no answer at all. That is how the tests check that a voice message is never sent twice and never lost.

`/fixture/verification` makes Nod wait for a code (`otp` or `payment`), and the next code sent is stored masked. `/fixture/handoff` opens or closes a browser handoff. While it is open, the fake server streams two small synthetic page images and counts the clicks, scrolls and keys it receives.

### Demo mode

`pnpm demo:server` runs the fake server as a public demo, for App Store review. Everything in it is synthetic: on first start it seeds an English sample conversation (Markdown, questions, files, an image and a voice note) and sample apps, schedules, usage and vault entries. Every message gets a scripted reply after about 1.5 seconds that walks through a question card, a file and Nod's browser, and Stop cancels it. It never calls a model or any other service.

| Variable                       | Meaning                                                                                                                                          |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `NOD_VALIDATION_PORT`          | Port to listen on.                                                                                                                               |
| `NOD_VALIDATION_TOKEN`         | The token the reviewer types on the connect screen, so treat it as their password. At least 43 letters, digits, `-` or `_`, as the app requires. |
| `NOD_VALIDATION_DATA`          | JSON file that keeps the conversation across restarts, capped at the last 200 messages. Delete it and restart to reset the demo.                 |
| `NOD_VALIDATION_HOST`          | Address to bind, `127.0.0.1` by default. Keep it behind an HTTPS reverse proxy.                                                                  |
| `NOD_VALIDATION_ORIGIN`        | The public address the app connects to, such as `https://demo.example.com`. Requests for any other host are refused.                             |
| `NOD_VALIDATION_CONTROL_TOKEN` | Optional. Without it every `/fixture/*` route answers 401.                                                                                       |

```sh
NOD_VALIDATION_PORT=4400 NOD_VALIDATION_TOKEN="$(openssl rand -hex 32)" \
  NOD_VALIDATION_DATA=/srv/nod-demo/store.json NOD_VALIDATION_ORIGIN=https://demo.example.com \
  pnpm demo:server
```

The proxy must pass the original `Host` and not buffer `/api/events` or `/api/browser-handoff/stream`. Uploaded files stay on the demo server and are served only with the token.

## What the tests cover

| Area             | Test                                                  | What it would catch                                                                                                                                                                                                                                                                                                                                       |
| ---------------- | ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Connecting       | `tests/connection.test.ts`, flow 1                    | A token sent to a plain-HTTP or credentialed address, a refused token treated as accepted.                                                                                                                                                                                                                                                                |
| Messages         | `tests/chat.test.ts`, flow 2                          | A message shown twice or lost when history and live updates overlap, or an unsent message that jumps below newer ones.                                                                                                                                                                                                                                    |
| Voice delivery   | `tests/delivery.test.ts`                              | A voice message sent twice after a lost answer, a Stop ignored, a delivered message resent after a restart, a send the server never answers left waiting forever, a text whose answer was lost waiting for the live connection instead of going again at once, a message sent on a quiet connection without renewing it, a discarded message sent anyway. |
| Attachments      | `tests/attachments.test.ts`, `tests/delivery.test.ts` | A file over 90 MB uploaded, a message sent before its files finished uploading.                                                                                                                                                                                                                                                                           |
| Links and images | `tests/links.test.ts`                                 | A reply loading an image from another site, or opening a `tel:` or other app link.                                                                                                                                                                                                                                                                        |
| Files            | `tests/files.test.ts`, flow 6                         | An HTML or SVG file rendered as a page instead of shown as text, a file missing from the panel or listed twice, or a panel that dragging its handle down doesn't close.                                                                                                                                                                                   |
| Working line     | `tests/chat.test.ts`, flow 4                          | Nod working with the Stop button showing but no working line, as when it continues a task after you answer a question.                                                                                                                                                                                                                                    |
| Browser handoff  | `tests/browser.test.ts`, flow 7                       | A page image lost when the stream splits it, a tap on the empty space around the page sent as a click, a handoff that closing the panel ends, or a Return to Nod the server never hears.                                                                                                                                                                  |
| Private codes    | `tests/chat.test.ts`, flow 8                          | A code shown in the chat or kept with the unsent messages, an ordinary reply masked, or the code card missing while Nod waits.                                                                                                                                                                                                                            |
| Live updates     | flow 3                                                | The app not reconnecting after the live connection drops.                                                                                                                                                                                                                                                                                                 |
| Questions        | flow 4                                                | A choice answered twice.                                                                                                                                                                                                                                                                                                                                  |
| Screens          | flow 5                                                | A screen in the menu that no longer opens.                                                                                                                                                                                                                                                                                                                |
